# 6. Video and audio outputs

## 6.1 What the Jaguar core emits

`rtl/jaguar.v` ports:

| Signal | Width | Notes |
|---|---|---|
| `vga_r`, `vga_g`, `vga_b` | 8 each | already 24-bit RGB out of `_pix`/`_cryrgb` |
| `vga_hs`, `vga_vs` | 1 | **positive** pulses (`video_mixer` is fed them directly) |
| `hblank`, `vblank` | 1 | from `_vid` (`rtl/Tom/vid.v:56-57`) |
| `interlaced` | 1 | `~vp[0]` — set when the programmed vertical period is even (`vid.v:829`) |
| `vid_ce` | 1 | pixel clock enable on `sys_clk` |
| `active_video` | input | selects "active" vs "original" visual area |

### Pixel rate

`rtl/jaguar.v:173-207`:

```verilog
wire [2:0] pix_ce_div;          // = ppn = VMODE[11:9] = PWIDTH   (Tom/vid.v:828, :303)
pix_ce_div_reg <= |pix_ce_div[2:1] ? 1'b1 : pix_ce_div[0];
                                // "don't allow it to go above 1 for
                                //  filter/resolution purposes"
assign vid_ce = xvclk & pix_pp;
```

So despite the Jaguar supporting PWIDTH 1-8, the MiSTer port deliberately
quantises to **exactly two pixel rates**:

| `PWIDTH` field | divider | pixel clock | typical mode |
|---|---|---|---|
| 0 | /1 | **26.590909 MHz** | ~640 px wide |
| 1-7 | /2 | **13.295454 MHz** | ~320 px wide |

`video_mixer` is parameterised `LINE_LENGTH(800)`, i.e. ≤800 active pixels/line.
Vertical counters `vc[10:0]`, horizontal `hc[10:0]` — programmable, so active
height varies per game (200/224/240/256/480i are all reachable).

## 6.3 APF video interface

`core_top` outputs:

| Signal | Requirement |
|---|---|
| `video_rgb[23:0]` | RGB, sampled on `video_rgb_clock` |
| `video_rgb_clock` | **the pixel clock itself**, supplied by the core |
| `video_rgb_clock_90` | the same clock, +90° phase. Must come from the same PLL. |
| `video_de` | active-pixel enable |
| `video_hs`, `video_vs` | sync |
| `video_skip` | drop one pixel clock — used to reconcile non-integer pixel rates |

`video.json` declares `scaler_modes` (width/height/aspect) and `display_modes`.

### Chosen approach

**Run `video_rgb_clock` at a fixed 26.590909 MHz and pixel-double in /2 mode.**

Rationale: because `jaguar.v` already clamps the divider to /1 or /2, a single
26.59 MHz video clock with each pixel held for two clocks in /2 mode produces a
**contiguous, constant-rate DE** stream in every video mode. No `video_skip`
juggling, no PLL reconfiguration, and the 26.59 MHz output is an exact /4 of
`clk_sys` from the same PLL, so `video_rgb_clock_90` is free.

Implementation sketch (new module, `target/pocket/jaguar_video.sv`):

```
clk_sys (106.36) domain:  latch {vga_r,vga_g,vga_b}, hs, vs, hblank, vblank on vid_ce
clk_vid (26.59)  domain:  emit one pixel per clock;
                          in /2 mode the same latched pixel is emitted twice
                          video_de = ~hblank & ~vblank
```

Because `clk_vid` is a synchronous /4 of `clk_sys` from one PLL, this is a
same-domain transfer with a known phase relationship — constrain it, don't
synchronise it.

### Interlace

`interlaced` is exported but MiSTer handles it by toggling `VGA_F1`
(`Jaguar.sv:43, 451-462`). APF's scaler has no field signal. Options, in
preference order:

1. Treat interlaced output as progressive at half vertical rate (will look
   wrong on 480i titles, fine for everything else).
2. Bob-deinterlace by line-doubling each field.
3. Weave into a field buffer — **not affordable**: 640×480×24 bit = 900 KB,
   vastly over BRAM, and would need external memory bandwidth we do not have.

Pick (1) for Milestone 4-5 and revisit at Milestone 6.

### Proposed `video.json` (starting point, refine at M4)

```json
{ "video": { "magic": "APF_VER_1", "scaler_modes": [
  { "width": 640, "height": 240, "aspect_w": 4, "aspect_h": 3, "rotation": 0, "mirror": 0 },
  { "width": 640, "height": 200, "aspect_w": 4, "aspect_h": 3, "rotation": 0, "mirror": 0 },
  { "width": 640, "height": 256, "aspect_w": 4, "aspect_h": 3, "rotation": 0, "mirror": 0 }
]}}
```

Width 640 for both pixel rates, because /2 mode is pixel-doubled to 640 in the
core. `auto_crt_ar` (which measures sync to derive aspect) becomes redundant and
can be dropped, or kept to drive a bridge register the host reads.

## 6.4 Audio

### What the core emits

`jaguar.v:54-55` → `aud_16_l[15:0]`, `aud_16_r[15:0]`, generated by
`tda1545a_inst` (`jaguar.v:1682-1696`), which models the real Jaguar's Philips
TDA1545A DAC fed by Jerry's I²S output (`i2s_clk`, `qws`, `i2s_data`). Signed
16-bit, `AUDIO_S = 1` on MiSTer (`Jaguar.sv:971`).

Sample rate: whatever Jerry's programmable SCLK divider produces — typically
~44.1 kHz-ish but **not** a fixed rate, and games change it.

### MiSTer side (deleted)

`AUDIO_L/R`, `AUDIO_S`, `AUDIO_MIX` → `sys/audio_out.sv` → I²S/SPDIF/ALSA/HDMI.

### APF side

`core_top` outputs `audio_mclk`, `audio_dac`, `audio_lrck`; the core must be an
**I²S master**. Pocket expects 48 kHz stereo.

Use `sound_i2s.sv` from `agg23/openfpga-SNES` verbatim
(`refs/openfpga-SNES/target/pocket/sound_i2s.sv`):

```verilog
sound_i2s #(.CHANNEL_WIDTH(16), .SIGNED_INPUT(1)) sound_i2s (
    .clk_74a    (clk_74a),
    .clk_audio  (clk_sys),          // whatever domain the samples are in
    .audio_l    (aud_16_l),
    .audio_r    (aud_16_r),
    .audio_mclk (audio_mclk),
    .audio_lrck (audio_lrck),
    .audio_dac  (audio_dac)
);
```

It generates `audio_mclk` by dividing `clk_74a` and resamples by simply latching
the current `audio_l/r` at each LRCK edge — a nearest-neighbour resample. That
is what every Pocket core does and it is adequate; Jaguar's variable sample rate
makes it *more* appropriate here than a fixed-ratio resampler.

**Milestone 1-2: tie `audio_dac`/`audio_lrck`/`audio_mclk` off.** Milestone 6:
wire `sound_i2s`. Add `osnotify_inmenu` muting at the same time.

### Audio open question to log

`tda1545a.v` is driven by `i2s_clk` derived from Jerry's SCLK. If the resulting
sample rate drifts far from 48 kHz the nearest-neighbour resample will alias
audibly. Measure the actual `dac_sample_strobe` rate on hardware at Milestone 6
and decide then whether a proper interpolating resampler is needed.
